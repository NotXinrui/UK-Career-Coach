# CV Tracks Template

A **track** is a CV version aimed at one role family. Applying with a single CV to every role usually dilutes the evidence; two to four tracks is a workable range. The coach recommends a track per JD, so each needs a clear definition.

## How to define a track

| Field | What to write |
|---|---|
| Name | A neutral label, such as "Delivery / PMO", "Digital transformation / AI", "Consulting / analysis" |
| File | Filename of the CV version |
| Target roles | Job titles it is meant for |
| Framing | What the first third of the page emphasises (governance and reporting, change and technology language, advisory and stakeholder framing, and so on) |
| Lead evidence | The 3–4 achievements that come first |
| Vocabulary | Terms this track uses on purpose |
| Not claimed | Things this track deliberately does not claim, even if the JD asks |

## How the coach uses tracks

1. Extract the JD's keywords and seniority signals.
2. Score each track by overlap and by whether the lead evidence matches what the JD values most.
3. Recommend one base track. Suggest borrowing a bullet from another track only when it is true and relevant.
4. Report which JD requirements no track can support. These are gaps, not instructions to add claims.

## Consistency checks across tracks

- Same dates, titles, employers and metrics everywhere.
- Same headline numbers (budget, team size, project count) in every version.
- Differences should be in emphasis and order, not in facts.

## Tip: showing your tracks publicly

If you publish an example, use a fictional person and fictional organisations. Real file names or employer-specific variants reveal where you applied.
